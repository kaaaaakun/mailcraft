# デザイン要件(オーナー決定の記録)

この文書は、GitHub Issue **#1〜#6**(label: `design` / `discussion`)で議論したデザイン方針について、
**オーナーが決めた内容** を 1 か所にまとめたものです。実装する人が「何を作ればよいか」「まだ決まっていないことは何か」を
ここだけで判断できるようにしています。

- 各項目の末尾の `[#N]` は、根拠になった Issue の番号です。
- オーナーは各 Issue で **「推薦案をすべて採用」** と回答しています(#3 は「全部後回し」、#4 は「実装も含めて悩みたい」、#5 は実装済みを承認)。
- この文書は **要件の記録のみ** です。ここに書いた内容の多くはまだ実装されていません(各項目の「状態」を参照)。
- モック画像と HTML は `docs/design-proposals/` にあります。モックは「見た目の議論用」で、実装の仕様ではありません。

> 用語メモ(初めての人向け)
> - **パレット**: 画面左の「ブロックを追加する道具箱」。
> - **プロパティパネル**: 画面右の「選択中のものを編集する欄」。
> - **トークン**: 色や余白に付けた「意味のある名前」(例: `danger` = 危険操作の色)。値を差し替えるだけで見た目全体を変えられる。
> - **プリセット**: トークンの値をまとめた「配色セット」(例: `neutral`)。

## 2. 詳細

### 2.1 全体の方向性 [#1]

オーナーのコメント: 「左は A、右は C。ただし色はブランドカラーもあるので引数で渡して、B みたいな感じがいい」

```
         密度・道具感              安心感・定番             色・親しみ
        ┌──────────┐            ┌──────────┐           ┌──────────┐
        │ A Dense  │            │ C Classic│           │ B Soft   │
        └────┬─────┘            └────┬─────┘           └────┬─────┘
             │左パレット              │右プロパティ            │色の付け方
             └───────────────┬───────┴──────────────────────┘
                             ▼
                     mailcraft の目標デザイン
```

- **左 = A**: 小さめの文字、見出しでグループ化、`T` `H` `B` などのショートカット表示。
- **右 = C**: アコーディオン(見出しをクリックで開閉)でプロパティを整理する、見慣れた形。
- **色 = B 風**: ブランドの色が UI にほんのり乗る。ただし色そのものはライブラリが決めず、**ホストが渡す**。
  - 引数: `theme.brand = { primary, secondary, normal }`(PR #8 で experimental として実装中)。
  - 担当: `primary` = 選択・フォーカス・主ボタン / `secondary` = 行の選択枠・バッジ・アイコン / `normal` = 文字・罫線・面の階調。

### 2.4 配色とテーマ API [#4]

オーナー回答: 「実装も含めて悩みたい」→ **方向性(推薦)は採用、細部は実装しながら決める**。

#### 目標の形(案。API 名は実装時に確定)

```ts
createEditor(el, {
  theme: {
    preset: 'neutral' | 'warm' | 'high-contrast', // まずプリセットを選ぶ
    mode: 'auto' | 'light' | 'dark',              // 既定 'auto' = OS 追従
    brand: { primary, secondary, normal },        // [#1] ホストのブランド色 (PR #8)
    tokens: {                                     // 細かく上書きしたいときだけ
      accent, onAccent,                           // onAccent は省略時に自動選択
      surface, surfaceRaised, surfaceSunken,      // 面の 3 階層
      border, borderStrong,
      text, textMuted,
      danger, success, warning,                   // 意味色
    },
    density: 'compact' | 'comfortable',           // [#2-6]
    radius, fontFamily,
    // 旧キー (accent / accentContrast / background / panel / border / text / muted) もエイリアスとして受け付ける
  },
});
```

#### 値が決まる順番(後ろほど優先)

```
 プリセット(neutral など)
   └─> mode(light / dark / auto→OSで決定)
         └─> brand(primary / secondary / normal から派生)
               └─> tokens / 旧キー(明示指定はそのまま使う)
                     └─> onAccent が未指定なら WCAG 比で自動選択
                           └─> コントラスト検査 → 不足なら console.warn のみ (色は変えない)
                                 └─> --mc-* CSS 変数へ書き出し (ホスト CSS から上書き可)
```

#### 決まっていること

| 項目 | 決定 | 出典 |
| --- | --- | --- |
| 意味色 | `danger` / `success` / `warning` を持つ | [#4] |
| 面の階層 | `surface` / `surfaceRaised` / `surfaceSunken` | [#4] |
| プリセット | `neutral`(既定)/ `warm` / `high-contrast`。色つきアイコンのバブルもプリセット扱い | [#4][#6] |
| 既定のアクセント | ニュートラル寄り・控えめ(現行の青 `#2f6fed` から変更) | [#2-2] |
| `mode` の既定 | `'auto'` | [#4] |
| コントラスト不足 | 警告のみ。自動補正しない | [#4] |
| `onAccent` | WCAG コントラスト比で白/黒などを自動選択 | [#4] |
| 旧キー | エイリアスとして残す | [#4] |
| メール本体 | テーマの対象外 | [#4] |

#### 実装しながら決めること(要検討)

- `brand`(#1 / PR #8)と `tokens`(#4)の関係: `brand.primary` → `accent`、`brand.normal` → `surface*` / `text*` / `border*` の派生とする案が自然だが、`secondary` をどのトークンに割り当てるか。
- `mode: 'auto'` を既定にすると、現在 `mode` 未指定でライト表示を前提にしているホストの見た目が変わる。既定の切替時期(メジャー更新扱いにするか)。
- 旧キーをいつまで残すか(Issue #4 の質問 6)。当面は無期限で残し、非推奨表示は別途判断。
- 警告の出し方(開発時のみか、常にか / `getTheme().warnings` のような取得 API を正にするか)。

### 2.5 レスポンシブレイアウト [#5]

- 8b8df87 で第 1 段階を実装済み、オーナーが承認(「ok 良さそう」)。
- 実装済みの内容: コンテナ幅(ResizeObserver)で判定、wide ≥ 1100px / compact 820–1100px(パレットがアイコンレール)/ stacked < 820px、
  `layout: { mode, breakpoints, sidebars: { left, right }, leftWidth, rightWidth }`、`setLayout` / `getLayout` / `getResolvedLayout` / `onLayoutChange`。
- Issue 本文の案との差: stacked の既定境界は 760px → **820px**、`sidebars` は `'show' | 'rail' | 'hide'` → **boolean** で実装。
